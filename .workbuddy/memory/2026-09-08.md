## v1.0.1 推送 GitHub 完成（push 挂起问题排查与解决）
- 现象：v1.0.1 提交（4c740e9）后 git push 反复失败——前台 push 被超时杀掉（SIGTERM 无输出），后台任务挂起 17 分钟无任何进展
- 根因：`credential.helper` 指向 `C:/Users/zhou/.workbuddy/binaries/PortableGit/.../git-credential-manager.exe`，在无 GUI 交互环境下授权弹窗永远不出现，进程挂死等输入
- 解决方案（已验证可复用）：读取已存 PAT（`/c/Users/zhou/.ghj_publish_token`，CRLF 需 `tr -d '\r\n'` 清洗）+ 内联 credential helper 推送：
  ```bash
  TOKEN=$(cat "$HOME/.ghj_publish_token" | tr -d '\r\n') && GIT_TERMINAL_PROMPT=0 timeout 60 git \
    -c credential.helper= \
    -c credential.helper='!f() { echo username=hzhou1734-pixel; echo password='"$TOKEN"'; }; f' \
    push -u origin main
  ```
- 遗留问题：push 成功（`* [new branch] main -> main`）但本地 `refs/remotes/origin/main` 未落盘，`git status -sb` 显示 `[gone]`
- 排查异常：`git fetch origin` 显示 `[new branch]` 但引用不可见；`.git/refs/remotes/` 目录为空、无 packed-refs；`git update-ref` 执行无报错但 show-ref/for-each-ref 均看不到（PortableGit 环境下 update-ref 异常）
- 修复：`mkdir -p .git/refs/remotes/origin && echo "4c740e9d71e449d7e66b096f03428d81e9577bb0" > .git/refs/remotes/origin/main && git branch --set-upstream-to=origin/main main`
- 最终验证：`git ls-remote` 确认远程 `refs/heads/main = 4c740e9`；`git status -sb` 输出 `## main...origin/main`（本地与远程完全同步）
- 经验：本机 PortableGit 环境下推 GitHub 一律跳过 git-credential-manager，直接用 PAT 内联凭证助手 + timeout 保护；push 后若出现 `[gone]` 先查 `.git/refs/remotes/` 实际文件
