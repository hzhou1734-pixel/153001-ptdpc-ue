## 顾好家 logo 显示问题（环境层面 443 图片域名不可用）
- 用户反馈"现在上传的所有图片全部显示异常"
- 根因排查：
  - 后端 baseUrl `https://likeadmin.l.440.red:9443`（API 通），但后端 `site_url` / 图片 base_url 配成了 `https://likeadmin.l.440.red`（443，无端口），与 9443 不同源
  - 443 端口图片服务器在该沙箱机器（即便 `curl -k`）也返回 `HTTP 000`/Connection Established 后无响应，证书/网络隔离问题
  - 9443 端口 `/uploads/images/...` 返回 404（纯 API 端口，不 serve 静态）
  - `file/lists` 显示系统所有已有素材的 url 也都指向 443 —— 表明这是整个开发环境的图片域名问题，不止顾好家 logo
- 实际方案：把顾好家 PNG 放到前端 `public/guhaojia-icon.png`（vite 直接 serve），用本地绝对路径 `/admin/guhaojia-icon.png` 回填 7 个图片字段，dev 200/18834B 验证通过
- 后续建议（用户如遇系统其他素材也异常）：
  - 全局：配置 vite proxy 代理图片到后端，或重写 `getImageUrl` 把 443 图片域名重定向到能访问的地址
  - 后端：修改 likeadmin 后端 `site_url` / OSS 配置为 9443 或同 origin 域名

## 存储/图片显示问题根因与修复（重要）
- 用户诉求：检查存储、修复本地存储，让图片顺利上传显示
- 排查结论：**存储配置本身正常** —— `/setting.storage/lists` 显示 local(本地存储) status=1 启用，qiniu/aliyun/qcloud 均关闭。上传接口也一直返回成功
- **真正根因**：后端把图片 URL 生成为 `https://likeadmin.l.440.red/uploads/...`（443），该域名 **SSL 握手失败**（curl 直连 exit 35 / vite 代理 500）；而 **http 80 端口完全正常**（旧图 8/28 上传的 200 可访问）
  - 9443 是纯 API 端口，不 serve 静态（/uploads 404）
  - 所以浏览器走 443 加载图片必然失败 → 表现为"所有图片显示异常"
- **修复方案**（前端可独立完成，无需改服务器）：
  1. `vite.config.ts` 加 `server.proxy`：`/uploads` → `http://likeadmin.l.440.red`（80，可用）。注意不能写 https(443)，否则代理 500
  2. `src/utils/util.ts` 新增 `normalizeImageUrl()`：把后端图片地址统一转成站内 `/uploads/...`（仅处理 /uploads 路径，不影响第三方 CDN）；支持 https 绝对地址、相对 `uploads/...` 两种输入
  3. `src/components/material/file.vue`（素材显示核心）+ `preview.vue`（预览）接入该函数
- 验证：`http://localhost:5173/uploads/images/20260908/20260908104239c00fb8774.png` → 200/18834B，端到端打通
- 网站信息页 7 个图片字段已回填为后端真实上传路径 `uploads/images/20260908/20260908104239c00fb8774.png`（走代理显示）
- 补充：素材库共 5 张图，其中 id=4（20260908104731b53da2774.png）在 80 端口也是 404，疑为单次上传写入异常，已改用 id=3 的图
